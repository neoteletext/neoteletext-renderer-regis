The stream

Terminal::feed reads a terminal data stream (manual chapter 1, "Entering and Exiting ReGIS").

BytesEffect
ESC P p or ESC P 0 pEnter ReGIS where it was last left, even in the middle of a command.
ESC P 1 pEnter ReGIS at a new command: an unfinished command is dropped, as by ;. The picture and every setting are kept.
ESC P 2 p, ESC P 3 pAs 0 and 1. The command display line is not drawn.
ESC \Leave ReGIS.
0x90, 0x9CThe 8-bit forms of ESC P and ESC \, obeyed only after Terminal::recognise_eight_bit_controls(true). They are off at first because both bytes occur inside UTF-8 text.
ESC, CAN (0x18), SUB (0x1A)End the string, as on a terminal.
Any other device control stringSkipped to its end (sixel, for example).
Everything outside a stringIgnored.

Only the first numeric parameter of the introducer is read. Terminal::feed_regis skips all of this and reads commands directly.

Syntax

ItemRule
Key letterOne of S W P V C T L R F, in either case. Arguments that follow belong to it until the next key letter. A new key letter restarts the line pattern and ends temporary write controls.
OptionsIn parentheses, nested as needed: V(W(I(R))). Nesting deeper than 32 is skipped.
Extent[x,y]. Either part may be left out; a part with a sign is relative. A stray character inside the brackets is ignored. A third value sets error 3.
NumberDecimal, with optional sign, fraction and power of ten (.1E3). Truncated to an integer and clamped to −32768…32767. An E with no digit after it is an option letter, not an exponent.
StringIn '…' or "…"; the quote mark doubled stands for itself. At most 1,024 bytes are kept. Only printable characters, CR, LF, BS and HT are kept.
Pixel vectorA digit 0 to 7 at command level: one step of the PV multiplier; 0 is right, 2 up, 4 left, 6 down, odd digits the diagonals. Directions are fixed on the screen whatever the addressing.
;Resynchronise: close everything open, wait for a key letter, clear the error report. Not special inside a string or a macrograph definition.
Spaces, commas, control charactersSeparate items and otherwise mean nothing outside a string.

S: screen control (manual chapter 2)

FormEffect
S(A[x1,y1][x2,y2])Display addressing: the corners of the coordinate system. One scale is used for both axes, the largest that keeps the area on the screen, so squares stay square; reversed corners reverse an axis. Both corners must be given in full.
S[x,y], S<pv>Scroll: the point named, in the stream's coordinates, becomes the top-left corner; a signed part is measured from the present corner. A pixel vector scrolls by the PV multiplier. What leaves the page is lost; what enters is the background.
S(M n(…) n(…))Output map location n, 0 to 15. Inside: H, L, S with numbers (hue 0 = blue, 120 = red, 240 = green; lightness and saturation in percent); or one letter of D R G B C Y M W; L alone is a grey. A is accepted and changes nothing, as on a VT340.
S(I n), S(I(…))Background: a location, or the location nearest a colour.
S(E)Erase the page being drawn on to the background. Also turns shading off, stops a curve and empties the position stack.
S(T n)Time delay: reported as Event::Wait; nothing waits.
S(P n)Show page 0 or 1.
S(C n)Cursor off or on: remembered (Terminal::cursor_visible), not drawn. Cursor styles C(H…), C(I…) are skipped.
S(W(M n))Temporary PV multiplier for a scroll.
S(H…)Hard copy: skipped.

W: write controls (manual chapter 3)

As a command the settings last; as an option of another command, V(W(…)), they last until the next key letter, the next temporary option or ;.

FormEffect
W(M n)PV multiplier: coordinates moved for each pixel-vector digit.
W(P n)One digit: standard pattern 0 to 9 (manual table 3-1). Two or more digits: the bits themselves, repeated to fill eight; of more than eight, the last eight.
W(P n(M m))Pattern multiplier, 1 to 16: pixels drawn for each pattern bit.
W(I n), W(I(…))Foreground: a location 0 to 15, or the location nearest a colour.
W(F n)Plane mask, 0 to 15: only these bits of a pixel change.
W(V)Overlay: pattern 1-bits write the foreground.
W(R)Replace: 1-bits write the foreground and 0-bits the background.
W(C)Complement: 1-bits invert the pixel's bits under the plane mask.
W(E)Erase: every pixel written takes the background, or with N1 the foreground.
W(N n)Negative: swaps pattern 1-bits and 0-bits.
W(S1), W(S0)Shading on (reference line: the row of the current position) and off.
W(S[,y]), W(S(X)[x])Shading to a horizontal line at y, or a vertical line at x.
W(S'c')Shading with a character: the top eight rows of its ten-row cell, at the text unit size in force, tiled from the screen's origin.

P: position (manual chapter 4)

FormEffect
P[x,y], P<pv>Move without drawing.
P(B) … (E)Save the position; (E) returns to it.
P(S) … (E)Save a placeholder; (E) moves nothing.
P(P n)Draw on page 0 or 1 from now on.
P(W(M n))Temporary PV multiplier.

Sixteen positions can be saved, shared with V. A seventeenth save sets error 7; an (E) with nothing saved sets error 8.

V: vector (manual chapter 5)

FormEffect
V[x,y], V<pv>Draw a line from the current position and move there.
V[]Draw the single pixel at the current position.
V(B) … (E)Save the position; (E) draws a line back to it.
V(S) … (E)Save a placeholder; (E) draws nothing.
V(W(…))Temporary write controls.

C: curve (manual chapter 6)

FormEffect
C[x,y], C<pv>Circle about the current position through the point. The cursor does not move.
C(C)[x,y]Circle about the point through the current position.
C(A d)[x,y]Arc of d degrees about the current position, starting at the point; positive is counterclockwise. The cursor does not move.
C(A d C)[x,y]Arc about the point, starting at the current position. The cursor ends at the arc's end.
C(S) p… (E)Open curve through the positions; drawn from the first given to the next to last. [] repeats a position, so one at each end draws the whole curve.
C(B) p… (E)Closed curve; the cursor returns to the start.
C(W(…))Temporary write controls.

Angles are rounded to whole degrees and clamped to ±360. (C) and (A) last until the next key letter. A curve is drawn as its points arrive, so one left without (E) still shows.

T: text (manual chapter 7)

FormEffect
T'string'Draw the string. Each character's cell has its top-left at the cursor, which then moves by the spacing. CR returns to where the text command began (moved down by any LF), LF moves down a display cell, BS back a space, HT forward one.
T(A n)Character set: 0 built in, 1 to 3 loadable. A character the set lacks is a solid block.
T(S n)Standard size 0 to 16 (manual table 7-3): sets display cell, unit cell and spacing. Out of range sets error 9.
T(S[w,h])Display cell: the area each character takes.
T(U[w,h])Unit cell: the size of the shape; width a multiple of 8 and height a multiple of 5, rounded down.
T(H n)Height multiplier, 1 to 256: both cells become 10n high.
T(M[w,h])Size multiplier: unit cell 8w by 10h; w at most 16.
T[x,y]Spacing: the move after each character, in the stream's coordinates.
T(D a)Tilt, to the nearest 45 degrees. The first in a group of options turns the string and its characters; a second in the same group turns the characters only.
T(I a)Italic: 0, ±22 or ±45 degrees as in the manual's table; positive leans the top left.
T<pv>Move half a display cell in that direction, relative to the string's baseline; half of an odd side rounds towards the top and left, as on a VT340: a nine-pixel cell moves four pixels right, five left.
T(B) … (E)Save and restore the text controls (sixteen deep).
T(W(…))Temporary write controls.
T(A0(L"…",R"…"))Character set designators: accepted and ignored; set 0 is always the supplied font.

In overlay writing only the lit pixels of a character are written; in replace writing the whole display cell is. The line pattern and shading do not apply to text; negative writing does.

L: load (manual chapter 8)

FormEffect
L(A n)Select set 1 to 3 for loading. 0 can be selected but not loaded; other numbers set error 4.
L(A'name')Name the set: ten characters, printable only, no quote marks.
L'c' hh,hh,…Load the cell called by character c: one pair of hexadecimal digits a row, top first, up to ten rows; a single digit is the right half of a row. End the cell with ;, a new string or a key letter from G to Z (the letters A to F are hexadecimal digits here).

@: macrographs (manual chapter 9)

FormEffect
@:x … @;Define macrograph x (a letter, either case). Nothing is drawn. An empty definition clears it.
@xInsert the macrograph's bytes into the stream; it may supply any part of a command.
@.Clear all twenty-six.

Macrographs nest sixteen deep; one already running is not started again; inside a running macrograph @: does not begin a definition. @ is ordinary text inside a quoted string.

R: report (manual chapter 10)

Each report is returned as Event::Reply, ending with a carriage return.

FormReply
R(P)[x,y]: the current position in the stream's coordinates.
R(E)"n,m": the last error code and the character at fault (manual table 10-1). Codes produced: 0, 1, 3, 4, 7, 8, 9.
R(L)A'name': the name of the set selected for loading.
R(M(=))"free,total" bytes of macrograph storage.
R(M(x))@=x, the contents, @;. The contents are left out unless Terminal::allow_macrograph_reports(true) was called, and then only their printable characters are sent.
R(I), R(I n)An empty line. No input cursor is shown.
R(P(I))No reply: Event::LocatorRequest is returned for the caller to answer.

F: polygon fill (manual chapter 11)

F(…) holds V, C, P and W commands. Nothing inside is drawn as lines; instead each vector's end, each V[], and each point of an arc, circle or curve becomes a vertex. At the closing parenthesis the polygon is filled and the cursor returns to where it was before the fill. P moves add no vertex. Write controls set inside the fill apply to the whole fill and end with it. Fewer than three vertices draw nothing; up to 4,096 are kept.

How shapes become pixels

ShapeRule
LineAn integer line from the first pixel to the last, both drawn. Each pixel takes the next pattern bit. A vector that continues from the pixel the last one ended on, within one command, does not draw that pixel twice.
Arc, circleThe starting point is turned about the centre one degree at a time and the points joined by lines ("the VT300 draws arcs in 1 degree increments").
CurveA Catmull-Rom spline, four points at a time, in straight pieces about six pixels long. The manual gives the properties of the curve but not its equation; this spline has those properties.
ShadingEach point drawn becomes a run of pixels to the reference line, both ends included. The pattern is read down the screen, one bit to a row.
FillThe even-odd rule along each pixel row, plus the outline, each pixel written once. The pattern is read down the screen as for shading.
TextThe stored shape is stretched over the unit cell by repeating pixels. At 45-degree tilts each step along the character is one diagonal pixel step, which stretches it as the manual describes.
ClippingAnything off the 800 by 480 page is not drawn; nothing wraps.

Limits

All in regis::limits. Past a limit the input is ignored or cut short, never an error.

LimitValuePast it
Coordinates−32,768 … 32,767Clamped
Parenthesis nesting32Deeper levels skipped
String1,024 bytesRest dropped
Extent text64 bytesRest dropped
Saved positions16Error 7
Saved text controls16Save ignored
Macrograph storage16,384 bytes in allThe definition is dropped
Macrograph nesting16Invocation ignored
Fill vertices4,096Rest ignored
Character cell side2,560 pixelsClamped
Work allowance16,000,000 units saved up; 256 earned for each byte fedDrawing skipped; LimitReached
Events in one call1,024Dropped; LimitReached
Reply bytes4,096 saved up; 1 earned for each byte fedReply dropped; LimitReached
Delay3,600 ticks (one minute) saved up; 1 earned for each byte fedCut; LimitReached
Font text1 MiBError::FontTooLong

A work unit is one pixel visited. Lines, shading, fills, text cells, erasing and scrolling all pay; an arc pays 4 units a degree; each byte run out of a macrograph costs 64 units. The budgets are credited byte by byte, so a stream is treated the same however it is divided between calls. If the allowance runs out inside a macrograph, the rest of it is dropped and the parser starts afresh at the next command.

Differences from a VT340

AreaThis renderer
Built-in charactersCome from the font the caller supplies. The shipped vt340.regisfont holds the VT340's own shapes, from its character generator ROM. Only one built-in set: designators for other sets are ignored.
Command display modeNot drawn (ESC P 2 p, 3 p).
Graphics cursors, input modes, locatorNot drawn or read; the caller is told (cursor_visible, LocatorRequest).
Hard copySkipped.
Time delayReported, within the delay budget; nothing waits.
Macrograph reportContents withheld unless allowed; printable characters only.
8-bit controls0x90 and 0x9C are ordinary bytes unless asked for.
Fill vertices4,096, where the VT340 keeps 256.
Macrograph storage16,384 bytes, where the VT340 has "at least 10,000".
Colour mapColours are kept as whole percentages, not the VT340's sixteen levels a primary. The power-up values are the manual's table; a real VT340 reports slightly darker greys.
Monochrome mapNone: there is one map, as the manual says of the VT340.
Text mixed with graphicsThere is no text screen; only ReGIS is drawn.
Circle edgesWithin a pixel of the VT340's, not identical.
